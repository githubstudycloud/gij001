# 日程提取提示词模板集

本文档包含多种场景下的提示词模板，可根据需求选择使用。

---

## 一、基础分类提示词

### 1.1 极简版（低成本）

```
判断以下文本是否包含日程安排（会议/约会/提醒/任务）。
仅回复JSON: {"has_schedule": true/false}

文本: {text}
```

### 1.2 标准版

```
你是一个日程信息识别助手。请判断以下文本是否包含日程安排信息。

日程信息的特征：
1. 包含时间表达（具体日期、相对时间如"明天"、时间点如"下午3点"）
2. 描述计划要做的事情
3. 可能涉及地点或人物

请以JSON格式回复：
{
  "has_schedule": true/false,
  "confidence": 0.0-1.0,
  "reason": "判断理由"
}

待分析文本：
{text}
```

## 二、完整提取提示词

### 2.1 结构化提取版

```
# 角色
你是专业的日程信息提取助手，擅长从自然语言中识别和提取日程安排。

# 任务
分析用户提供的文本，完成以下工作：
1. 判断是否包含日程信息
2. 提取所有日程要素

# 日程要素定义
- **时间(time)**: 事件发生的时间，包括：
  - 绝对时间：2024年1月15日、1月15日
  - 相对时间：明天、下周一、三天后
  - 时间点：上午10点、下午3:30
  - 时间段：上午、晚上、全天

- **事件(event)**: 要做的事情，如会议、约会、提交报告

- **地点(location)**: 事件发生地点，可选

- **参与人(participants)**: 涉及的人员，可选

- **类型(type)**: meeting/reminder/task/appointment

- **优先级(priority)**: high/medium/low

# 输出格式
严格使用以下JSON格式输出：
{
  "has_schedule": boolean,
  "schedule_count": number,
  "schedules": [
    {
      "time_raw": "原始时间表达",
      "time_type": "absolute/relative/range",
      "event": "事件描述",
      "location": "地点或null",
      "participants": ["参与人"],
      "type": "事件类型",
      "priority": "优先级"
    }
  ],
  "analysis": "简短分析"
}

# 待分析文本
{text}
```

### 2.2 带时间解析版

```
你是日程助手，请分析文本并提取日程信息。

## 特别要求
对于时间表达，请同时提供：
1. 原始表述
2. 解析后的标准格式（基于当前时间: {current_datetime}）

## 输出格式
{
  "has_schedule": boolean,
  "schedules": [
    {
      "time_original": "明天下午3点",
      "time_parsed": {
        "start": "2024-01-16T15:00:00",
        "end": null,
        "is_all_day": false
      },
      "event": "事件",
      "location": null,
      "participants": []
    }
  ]
}

## 待分析
{text}
```

## 三、Few-shot 提示词

### 3.1 分类Few-shot

```
分析文本是否包含日程信息。

### 示例

输入: "今天天气不错"
输出: {"has_schedule": false, "reason": "仅描述天气，无安排"}

输入: "记得明天交报告"
输出: {"has_schedule": true, "reason": "有时间(明天)和任务(交报告)"}

输入: "周三10点在会议室开周会"
输出: {"has_schedule": true, "reason": "有完整的时间、地点、事件"}

输入: "上次会议讨论得很好"
输出: {"has_schedule": false, "reason": "描述过去事件，非未来安排"}

输入: "如果有时间我们聊聊"
输出: {"has_schedule": false, "reason": "条件性表述，非确定安排"}

### 现在分析
输入: "{text}"
输出:
```

### 3.2 提取Few-shot

```
从文本中提取日程信息。

### 示例1
输入: "明天上午10点我们在星巴克见面讨论合作方案"
输出: {
  "has_schedule": true,
  "schedules": [{
    "time": "明天上午10点",
    "event": "见面讨论合作方案",
    "location": "星巴克",
    "participants": [],
    "type": "meeting"
  }]
}

### 示例2
输入: "下周一到周三出差北京，周二下午拜访客户"
输出: {
  "has_schedule": true,
  "schedules": [
    {
      "time": "下周一到周三",
      "event": "出差",
      "location": "北京",
      "type": "task"
    },
    {
      "time": "周二下午",
      "event": "拜访客户",
      "location": "北京",
      "type": "appointment"
    }
  ]
}

### 示例3
输入: "每周五下午4点团队周会"
输出: {
  "has_schedule": true,
  "schedules": [{
    "time": "每周五下午4点",
    "event": "团队周会",
    "recurrence": "weekly",
    "type": "meeting"
  }]
}

### 请分析
输入: "{text}"
输出:
```

## 四、特殊场景提示词

### 4.1 模糊时间处理

```
分析文本中的日程信息，特别注意处理模糊时间表达。

## 模糊时间处理规则
- "最近" → 未来1-3天
- "这几天" → 未来2-4天
- "月底" → 当月最后3天
- "尽快" → 标记为高优先级，时间待定
- "有空时" → 标记为低优先级，时间待定

## 输出格式
{
  "has_schedule": boolean,
  "schedules": [{
    "time_expression": "原始表达",
    "time_clarity": "clear/fuzzy/pending",
    "time_suggestion": "建议的具体时间范围",
    "event": "事件",
    "priority": "high/medium/low"
  }]
}

文本: {text}
```

### 4.2 多日程提取

```
从文本中提取所有日程安排。一段文本可能包含多个独立的日程。

## 注意事项
1. 识别所有独立的日程安排
2. 正确关联时间与对应事件
3. 处理隐含的日程（如"然后去..."暗示另一个安排）

## 输出格式
{
  "total_schedules": number,
  "schedules": [
    {
      "index": 1,
      "time": "时间",
      "event": "事件",
      "dependency": null  // 或依赖的日程index
    }
  ]
}

文本: {text}
```

### 4.3 日程冲突检测

```
分析文本中的日程，并检测潜在的时间冲突。

已有日程列表：
{existing_schedules}

新文本：
{text}

请分析：
1. 新文本中的日程信息
2. 与已有日程的冲突情况

输出格式：
{
  "new_schedules": [...],
  "conflicts": [
    {
      "new_schedule": "新日程描述",
      "existing_schedule": "冲突的已有日程",
      "conflict_type": "overlap/same_time/too_close",
      "suggestion": "建议处理方式"
    }
  ]
}
```

## 六、提示词优化建议

### 6.1 提高准确率
1. 添加更多few-shot示例，特别是边界case
2. 明确定义什么是日程，什么不是
3. 使用Chain-of-Thought让模型展示推理过程

### 6.2 降低成本
1. 使用更短的提示词
2. 限制输出长度
3. 对简单case使用极简版提示词

### 6.3 处理特定领域
1. 添加领域特定的示例
2. 定义领域特定的术语
3. 调整输出字段以匹配业务需求
