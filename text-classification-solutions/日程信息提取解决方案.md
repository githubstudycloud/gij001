## 需求分析

### 核心任务
- **文本分类**：判断一段文本是否包含日程相关信息
- **信息提取**：从文本中提取具体的日程要素（时间、地点、事件、参与人等）

### 日程信息特征
- 时间表达：具体日期、相对时间（明天、下周一）、时间段
- 事件描述：会议、约会、提醒、任务等
- 地点信息：线上/线下地点
- 参与人员：相关人员或组织

## 方案一：LLM直接调用

### 技术架构
```
用户文本 → LLM API → 分类结果 + 结构化日程数据
```

### 推荐模型

#### 1. OpenAI GPT-4o / GPT-4o-mini
- **优势**：理解能力强、中文支持好、结构化输出稳定
- **API成本**：GPT-4o约$2.5/1M tokens，GPT-4o-mini约$0.15/1M tokens
- **推荐用途**：高精度需求

#### 2. Claude 3.5 Sonnet / Claude 3 Haiku
- **优势**：推理能力强、长文本处理好、响应速度快
- **API成本**：Sonnet约$3/1M tokens，Haiku约$0.25/1M tokens
- **推荐用途**：复杂文本分析

#### 3. 通义千问 (Qwen)
- **优势**：中文优化、国内访问稳定、成本较低
- **API成本**：约¥0.008/千tokens
- **推荐用途**：国内部署、成本敏感

#### 4. 智谱 GLM-4
- **优势**：中文能力强、本土化支持好
- **API成本**：约¥0.1/千tokens
- **推荐用途**：国内企业应用

### 实现示例（Python）
```python
import openai

def classify_schedule(text: str) -> dict:
    response = openai.chat.completions.create(
        model="gpt-4o-mini",
        messages=[
            {"role": "system", "content": SYSTEM_PROMPT},
            {"role": "user", "content": text}
        ],
        response_format={"type": "json_object"}
    )
    return response.choices[0].message.content
```

### 优缺点
| 优点 | 缺点 |
|------|------|
| 开发速度快 | API调用成本 |
| 无需训练数据 | 依赖网络 |
| 泛化能力强 | 响应延迟 |
| 易于迭代优化 | 数据隐私考虑 |

## 方案二：LLM微调

### 技术架构
```
训练数据 → 微调基座模型 → 部署私有模型 → 推理服务
```

### 推荐基座模型

#### 1. Qwen2.5系列 (推荐)
- **规格**：0.5B / 1.5B / 7B / 14B / 72B
- **优势**：中文能力顶尖、开源免费、微调生态完善
- **推荐配置**：7B版本，适合单卡微调

#### 2. Llama 3.1系列
- **规格**：8B / 70B / 405B
- **优势**：社区活跃、工具链成熟
- **推荐配置**：8B版本

#### 3. ChatGLM3-6B
- **优势**：中文优化、资源占用低
- **适用**：资源受限环境

### 微调方法

#### LoRA/QLoRA（推荐）
```python
# 使用 transformers + peft 进行LoRA微调
from peft import LoraConfig, get_peft_model

lora_config = LoraConfig(
    r=16,
    lora_alpha=32,
    target_modules=["q_proj", "v_proj"],
    lora_dropout=0.05,
    task_type="CAUSAL_LM"
)
```

### 训练数据需求
- **最小数据量**：500-1000条标注样本
- **推荐数据量**：5000-10000条
- **数据格式**：
```json
{
  "instruction": "判断以下文本是否包含日程信息，并提取相关内容",
  "input": "明天下午3点我们开个会讨论项目进度",
  "output": {
    "has_schedule": true,
    "schedule": {
      "time": "明天下午3点",
      "event": "开会",
      "topic": "讨论项目进度"
    }
  }
}
```

### 部署方案
- **vLLM**：高性能推理引擎
- **Ollama**：本地部署简单
- **Text Generation Inference (TGI)**：HuggingFace官方方案

### 优缺点
| 优点 | 缺点 |
|------|------|
| 长期成本低 | 需要训练数据 |
| 数据隐私可控 | 初期投入大 |
| 可离线运行 | 需要GPU资源 |
| 针对性优化 | 维护成本 |

## 方案三：传统NLP+规则引擎

### 技术架构
```
文本 → 分词 → 特征提取 → 分类器 → 规则引擎 → 结果
```

### 推荐工具

#### 1. BERT系列分类模型
- **chinese-bert-wwm**：中文BERT
- **chinese-roberta-wwm-ext**：RoBERTa增强版

#### 2. 实体识别 (NER)
- **LAC (百度)**：词法分析
- **HanLP**：多功能NLP工具
- **SpaCy + zh_core_web**：工业级NLP

#### 3. 时间解析
- **dateparser**：多语言时间解析
- **jionlp**：中文时间表达提取

### 实现示例
```python
import jionlp as jio

# 时间提取
time_result = jio.parse_time("明天下午3点开会")
# 输出: {'time': ['明天下午3点'], 'type': 'time_point'}

# 结合BERT分类
from transformers import BertForSequenceClassification
model = BertForSequenceClassification.from_pretrained(
    "bert-base-chinese",
    num_labels=2
)
```

### 优缺点
| 优点 | 缺点 |
|------|------|
| 运行成本最低 | 开发周期长 |
| 完全离线 | 泛化能力有限 |
| 可解释性强 | 规则维护复杂 |
| 响应速度快 | 难以处理复杂表达 |

## 方案四：混合方案（推荐）

### 技术架构
```
文本 → 快速预分类(规则/小模型) →
       ├─ 明确日程 → 规则提取
       ├─ 明确非日程 → 直接返回
       └─ 不确定 → LLM深度分析
```

## 提示词模板

### 模板一：分类判断（简洁版）

```
你是一个日程信息识别助手。请判断以下文本是否包含日程安排信息。

日程信息的特征包括：
- 包含具体或相对的时间表达（如"明天"、"下午3点"、"周五"）
- 描述计划要做的事情（如"开会"、"约见"、"提交"）
- 可能包含地点或参与人员

请以JSON格式回复：
{
  "has_schedule": true/false,
  "confidence": 0-1之间的置信度,
  "reason": "简短的判断理由"
}

待分析文本：
{text}
```

如果包含日程信息，请提取以下要素：
- 时间：具体时间或时间范围
- 事件：要做什么事情
- 地点：在哪里（如有）
- 参与人：涉及谁（如有）
- 提醒：是否需要提醒

## 输出格式（JSON）
{

### 场景推荐

#### 🚀 快速验证/MVP阶段
**推荐：方案一（LLM直接调用）**
- 使用GPT-4o-mini或通义千问
- 配合提示词模板二
- 预计开发时间：1-2天

#### 💼 企业级生产环境
**推荐：方案四（混合方案）**
- 规则层处理高频模式
- 小模型处理中等复杂度
- LLM处理边界case
- 预计开发时间：2-3周

#### 🔒 高隐私要求场景
**推荐：方案二（LLM微调）**
- 基座模型：Qwen2.5-7B
- 本地部署：vLLM + Docker
- 预计开发时间：3-4周（含数据标注）

#### 💰 极致成本控制
**推荐：方案三（传统NLP）**
- BERT分类 + JioNLP时间解析
- 完全离线运行
- 预计开发时间：4-6周
